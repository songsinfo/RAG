# PRD-07 Agent 深入问答

版本：1.0 · 状态：规格已编写，未实现。依赖普通 RAG、权限、引用、会话与评估能力。

## Problem Statement

部分问题需要先获取中间信息，再决定下一次检索。例如先查“订单异常由哪个补偿任务处理”，再查对应任务的排障流程。固定一次召回可能遗漏中间关系，但无限工具循环会增加费用且可能重复执行。

## Solution

提供用户主动选择的深入问答模式，由一个 Agent 根据工具结果继续检索。Java 控制循环、工具调用、权限、消息、预算和终止。所有读取复用既有知识服务，最终答案采用与普通 RAG 相同的证据规则。

## User Stories

1. 作为用户，我希望复杂问题可以深入检索，以便找到跨文档的中间关系。
2. 作为用户，我希望仍可使用普通问答，以便简单问题不承担多轮成本。
3. 作为用户，我希望知道深入模式处于哪一步，以便判断等待时间。
4. 作为用户，我希望可以取消深入问答，以便停止不再需要的任务。
5. 作为用户，我希望达到预算后有明确说明，以便不把未完成当完整答案。
6. 作为用户，我希望工具只能读取有权访问的资料，以便 Agent 不扩大权限。
7. 作为用户，我希望最终结论引用实际读取的原文，以便核查多步推理。
8. 作为管理员，我希望循环轨迹记录真实调用和结果标识，以便排查重复检索。
9. 作为管理员，我希望无效工具或参数受到约束，以便防止模型任意执行。
10. 作为管理员，我希望简单重试不能改变业务规则，以便失败恢复不产生错误事实。
11. 作为评测维护者，我希望相同多跳题比较普通与深入模式，以便证明 Agent 的价值。
12. 作为项目负责人，我希望能解释模型决策与 Java 执行的边界，以便真正理解 Harness。

## Implementation Decisions

### 工具与循环

仅提供两类只读工具：search_knowledge（在当前授权范围内查询）和 read_section（按文档、版本、章节读取原文）。工具名和参数遵循严格契约；用户身份、租户、预算和权限不在模型可修改参数中。

循环行为：准备经过权限检查的上下文 → 调用模型 → 若有工具请求则验证并执行 → 保存助手工具调用和带对应调用标识的工具结果 → 下一轮；若模型输出最终答案则进入正常引用/可选语义验证 → 返回终态。

- search_knowledge 使用本次检索配置；如果配置含 HyDE 等嵌套模型调用，必须消耗同一全局预算，不能每次工具调用重新获得整份额度。
- read_section 只读取当前会话范围内可访问的资料，默认使用本次可接受版本；若版本在执行中变化，记录变化并避免混合不同版事实，必要时重新检索。
- 每个实际读取来源进入 evidence 集合，父块和图片同样登记。最终引用仅可指向该集合；无结果不等于成功检索了证据。
- 允许模型根据缺失信息更换查询，不允许无限重复相同工具与参数。重复阈值、模型轮数、总工具数、token 和总时长都受限。
- 初始试验上限可从 6 次主循环模型调用、8 次工具调用、60 秒总时长开始；嵌套模型调用另外计入全局计数和 token 预算。具体值由实测锁定，不当作承诺延迟。
- 工具失败返回结构化错误供有限恢复，鉴权拒绝不能通过重写 tenant/user 或放宽范围恢复。不能让模型擅自修改文档、指标口径或执行任意代码。

### 终态与用户体验

必须区分完成、部分可答、证据不足、冲突待澄清、模型/工具失败、重复调用终止、预算耗尽、用户取消和验证失败。

预算耗尽不标成任务成功；如已有部分证据，只有经正常验证的部分内容可显示，并明确未完成。系统不可为“生成最终总结”突破已经耗尽的预算。

页面展示“检索资料/读取章节/生成/校验”等可观察阶段及简洁进度，不展示模型内部推理。最终正文在校验后一次返回，取消和历史规则与普通模式一致。

取消阻止后续工具和模型调用，尝试中断可取消连接，迟到结果不复活已取消运行；外发前复核资料权限，不能撤回此前已外发内容。

## Testing Decisions

从问答 API 触发深入模式，用可控模型输出序列构造“搜索 → 读章节 → 再搜索 → 最终回答”，验证结果、证据、预算与终态。真实模型在同一多跳题集比较收益和代价；不以写死必须调用 N 次工具代表成功。当前没有既有 Agent 实现或测试。

| 编号 | Given / When / Then |
|---|---|
| AC-07-01 | 给定答案依赖一个中间实体的问题，当 Agent 先检索得到实体再查询时，最终答案能关联两步真实证据；普通基线结果同时保留。 |
| AC-07-02 | 给定模型产生未知工具、非法参数或越权章节 ID，当执行时，工具不被调用或读取受限正文，并产生明确错误结果。 |
| AC-07-03 | 给定检索工具内部调用了查询增强模型，当累计达到全局预算时，不因进入新一轮而重置额度。 |
| AC-07-04 | 给定模型反复发出相同工具参数，当达到重复限制时，返回明确终态，不无限循环。 |
| AC-07-05 | 给定模型没有工具调用但给出伪造引用，当结束时，仍须引用校验，不能因自然停止就认定任务正确。 |
| AC-07-06 | 给定用户取消与工具响应并发，当取消已被接受时，不再执行下一工具或追加正常最终答案。 |
| AC-07-07 | 给定执行中撤权或版本变化，当后续读取/生成时，重新核验并中止或重查，不能继续混用失效证据。 |
| AC-07-08 | 给定模型调用预算耗尽，当整理结果时，不偷偷追加超预算的总结调用，也不返回完成状态。 |
| AC-07-09 | 给定固定多跳和简单题集，当对照普通/深入模式时，报告成功率、工具次数、延迟、费用和终止分布。 |

## Out of Scope

Multi-Agent、任务 DAG、自动路由模型、写入业务系统、代码沙箱、长期记忆、无限反思、自我修改代码和保证 Agent 总优于普通 RAG。

## Further Notes

学习时用 S15 理解循环和执行边界，但不照搬其调度、团队协作、文件执行等机制。深入模式最终是否默认开放及配置值，由完整评估证据决定。
