# PRD-01 身份、租户归属与文档权限

版本：1.0 · 状态：规格已编写，未实现。依赖 PRD-00；本文件是各模块权限语义的权威来源。

## Problem Statement

不同团队需要共享部分文档、限制部分文档。只隐藏页面入口无法阻止用户直接读取 API、引用或历史内容。把部门等同于知识库会迫使排障资料重复存储，也不能表达跨团队共享。

## Solution

使用本地账号、用户组、固定维护管理员和文档级读者授权。知识库用于组织资料；文档可继承知识库默认读者或收紧范围。所有后端读取和维护入口执行一致鉴权。不给用户建设复杂的角色、菜单和审批系统。

## User Stories

1. 作为用户，我希望登录后仅看到可读资料，以便安全地使用共同平台。
2. 作为运营用户，我希望被加入读者组后能够查看技术排障指南，以便跨团队协作。
3. 作为用户，我希望退出登录后请求失效，以便结束访问会话。
4. 作为管理员，我希望按组授权，以便不必逐人维护每篇文档。
5. 作为管理员，我希望对个别用户授权，以便覆盖跨团队临时协作。
6. 作为管理员，我希望新文档默认不公开，以便检查完成前不误分享。
7. 作为管理员，我希望文档可继承知识库读者，以便批量调整常规访问范围。
8. 作为管理员，我希望文档可进一步限制读者，以便保护特殊资料。
9. 作为管理员，我希望资料更新继承同一文档 ACL，以便新版本不会意外扩大访问。
10. 作为用户，我希望无法伪造别人的身份或租户，以便资料边界可靠。
11. 作为管理员，我希望撤权影响所有检索和读取入口，以便派生数据不绕过授权。
12. 作为用户，我希望历史回答遵守当前权限，以便旧消息不泄露已撤权内容。
13. 作为管理员，我希望授权变更有审计，以便排查误共享。
14. 作为评测维护者，我希望实验按测试用户身份执行，以便真实验证权限。

## Implementation Decisions

### 身份与操作权限

- 第一版初始化运营、产品、技术示例用户及组，以及固定维护管理员；不连接企业目录/SSO。密码不能明文保存，登录会话由服务端验证。
- 每次请求从登录态解析用户和租户，不接受请求正文或工具参数直接授予身份。指定资源 ID 后再验证归属。
- 普通用户可读授权资料、管理本人会话与反馈；文档新增/发布/删除、ACL 修改、任务重试、策略发布和评测管理仅限维护管理员。
- 管理员的维护资格不自动授权正文读取。预览文档和查看包含正文的轨迹仍需文档读权限；新上传文档为上传者建立显式读权限。
- 管理员可修改本租户 ACL，所有变更留痕；不能修改另一租户资源。这是受信任的维护角色，不承诺抵御它故意自授权读取本租户内容。
- 知识库读者范围可包含全员、组或指定用户。文档采用“继承”或“限制”两种模式：限制模式为知识库读者与文档允许读者的交集。组和用户允许项取并集；不引入显式 deny 优先级体系。
- 为某份文档新增跨团队读者时，先使其进入知识库允许范围，再配置文档权限；界面应提示“文档允许项不会突破知识库范围”。
- ACL 不随历史版本复制成可绕过当前权限的旧规则，所有版本使用当前文档 ACL。

### 状态与读取规则

| 资源/动作 | 行为 |
|---|---|
| 文档列表/搜索建议/统计 | 普通用户只见可读且适当状态的条目；不能通过标题、计数或路径泄露受限资料 |
| 普通检索/模型上下文 | 仅当前生效且可读内容；过滤后不足不能放宽 ACL |
| 父章节、摘要、假设问题、OCR、图片及表格 | 与所属文档同租户同权限；关联必须校验，不单凭传来的 ID 回查 |
| 引用 | 当前仍可读且未删除时，可以读取该引用对应的历史版本；不能默默改指新版 |
| 历史回答 | 任一实际上下文证据失去权限时隐藏整条回答与来源；不仅检查最终显示的引用 |
| 运行中撤权 | 在新的证据外发和最终展示前检查；不发送新的受限内容，抑制相关结果；无法撤回此前已送达的数据 |
| 授权重新恢复 | 文档状态及当前 ACL 允许时历史可重新显示；已彻底删除的内容不能复活 |
| 评测/导出/审计 | 运行身份与查看身份分别鉴权；包含正文的资料不得因管理员入口而直接公开 |

共享索引的搜索前置过滤与权威状态复核都要实现。缓存或后台处理不能在查找成功后省略鉴权。应用源码、操作系统和数据库管理员不属于本产品 ACL 能限制的威胁范围。

### 数据与接口契约

需表达租户、用户、组、组成员、维护资格、知识库读者、文档 ACL、授权变更事件及会话所有者。关联资源必须同租户，关键唯一约束包含适用的租户范围。

接口覆盖登录/退出、本人信息、知识库列表、文档授权查询与变更。维护入口至少区分未登录、无操作资格、资源不可访问、参数无效；对无阅读权限用户不区分“受限文档存在”与“不存在”。具体 HTTP 路径和错误码在 API 设计统一。

## Testing Decisions

从应用 API 使用不同会话访问同一资源，覆盖正文、元数据、图片、引用、历史、导出和工具读取；不只测试权限辅助函数。使用两个租户、三个用户组、个人授权和没有任何授权的账号。当前没有既有权限测试可复用。

| 编号 | Given / When / Then |
|---|---|
| AC-01-01 | 给定运营无权的技术文档，当运营搜索精确标题、请求已知文档/图片 ID 或读取来源时，不得到标题、正文、图片和路径。 |
| AC-01-02 | 给定同名文档位于另一租户，当账号伪造租户参数或文档 ID 时，查询及维护请求均不能跨租户成功。 |
| AC-01-03 | 给定文档继承知识库权限，当组成员被移除后，新请求不能检索或读取该文档。 |
| AC-01-04 | 给定限制模式文档，当用户在文档允许列表但不在知识库读者范围内时，仍不可读。 |
| AC-01-05 | 给定普通用户，当直接调用删除、授权、策略发布和评测管理接口时，即使绕过前端也被拒绝。 |
| AC-01-06 | 给定旧回答使用了两段证据，当未显示引用的其中一段被撤权时，历史回答也必须隐藏且不用于追问。 |
| AC-01-07 | 给定管理员无文档阅读授权，当查看预览或包含正文的评测详情时，不能以维护资格直接绕过阅读检查。 |
| AC-01-08 | 给定流转中的问答，当证据发送后、结果返回前撤权时，不能展示受影响答案；已经外发的事实记录准确，不声称已撤回。 |
| AC-01-09 | 给定仍授权且未删除的旧版引用，当当前版更新时，读取引用仍定位旧版原文并注明已非当前版。 |

## Out of Scope

SSO/LDAP、复杂 RBAC/ABAC 配置平台、段落/表格单元格级 ACL、显式 deny 规则、授权审批流、商业租户注册和对数据库管理员的隔离。

## Further Notes

用户要求“页面控制、不用考虑”在后续确认中收敛为“不做复杂操作权限产品”；Q26 已确认固定维护管理员。后端基本鉴权仍是必须实现的安全边界。

权限撤销不是数据擦除。回收站、彻底删除与运行制品清理由 PRD-02/06 定义；任何保留内容仍受本文件规则约束。
