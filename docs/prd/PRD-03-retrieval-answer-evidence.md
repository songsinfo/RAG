# PRD-03 检索、回答与证据

版本：1.0 · 状态：规格已编写，未实现。依赖 PRD-01/02，与 PRD-05 共用版本化配置。

## Problem Statement

用户问法与文档表达不同，关键词和向量召回各有遗漏；多个候选又可能重复或缺少前提。来源列表不能证明答案中的每个事实受到支持。系统需要可控制、可评估的检索流程和真实的证据关联。

## Solution

在授权范围内运行可配置的查询增强、召回和后处理，将命中映射回原文、按预算构建上下文，生成带事实与证据关系的答案。普通用户直接提问，管理员在实验中选择策略。无证据、冲突、失败及预算终止均明确返回。

## User Stories

1. 作为用户，我希望错误码和接口名可精确搜索，以便定位排障文档。
2. 作为用户，我希望换一种说法也能找到资料，以便不必记住原文词语。
3. 作为用户，我希望追问被转换成完整问题，以便继续检索。
4. 作为管理员，我希望启用 HyDE，以便测试假想文档是否补足语义召回。
5. 作为管理员，我希望启用 Multi-Query，以便比较多角度检索的覆盖收益。
6. 作为管理员，我希望分别运行 Dense 和 BM25，以便建立可解释的基线。
7. 作为管理员，我希望通过 Hybrid 与 RRF 合并结果，以便组合两类检索优势。
8. 作为管理员，我希望区分原文、摘要和假设问题的命中，以便理解多向量贡献。
9. 作为用户，我希望候选不过度重复，以便答案覆盖问题的不同方面。
10. 作为管理员，我希望比较 MMR 开关，以便验证多样性是否真正有益。
11. 作为用户，我希望重排后留下更相关的材料，以便减少无关答案。
12. 作为用户，我希望命中短块后补充必要上下文，以便不遗漏条件和例外。
13. 作为用户，我希望每个重要事实有具体证据，以便核查回答。
14. 作为用户，我希望图片和表格引用能打开相应原始材料，以便检查机器解析。
15. 作为用户，我希望资料不足时明确拒答或部分回答，以便不把猜测当规则。
16. 作为用户，我希望不同文档冲突时分别列出，以便补充适用条件。
17. 作为管理员，我希望严格模式检查语义证据支持，以便评估是否值得额外成本。
18. 作为管理员，我希望策略调用受预算控制，以便组合不会无限扩张。
19. 作为管理员，我希望配置有版本且可回退，以便复现和恢复默认行为。
20. 作为用户，我希望最终回答校验后才出现，以便不先看到未通过检查的内容。

## Implementation Decisions

### 查询与召回契约

普通问答输入为问题、会话、资料范围和用户可选的普通/严格模式；身份由登录态给出。用户不能自行设置管理员策略配置。运行固定本次配置版本与语料构建标识，实际命中文档版本记录在证据中。

| 能力 | 输入与结果 | 约束 |
|---|---|---|
| Rewrite | 原问题与经过权限检查的会话上下文 → 独立查询 | 保留原问题；失败可以按配置退回原查询，必须标记降级 |
| HyDE | 问题 → 假想文档 → Dense 查询向量 | 不作为事实或引用；限定长度、数量和调用预算 |
| Multi-Query | 问题 → 多个检索表达 | 去重、保留原查询入口；限制查询数，不生成越权范围 |
| Dense | 查询向量 → 表示记录/候选 | 模型和维度兼容，含租户、ACL 范围过滤；语义近邻不保证有答案 |
| Sparse | 查询文本 → BM25 原文候选 | 第一版 Sparse 明确指 BM25；中文与错误码分析在技术设计验证 |
| Hybrid | Dense 与 Sparse → 多路候选 | 原始排名、分数、渠道和耗时保留；不直接相加不同尺度分数 |

普通问题初始使用原查询 Hybrid；有追问时可启用 Rewrite。HyDE 和 Multi-Query 不要求默认同时启用。实验可指定独立组合并保存生成的查询文本；生成的假设问题索引与查询侧 Multi-Query 分开记录。

### 候选处理顺序

拟定默认顺序：渠道内映射并去重 → RRF → 权威权限/版本校验及原文回查 → Reranker → 可选 MMR → 可选父章节扩展/去重 → 上下文预算检查 → 生成。顺序由技术设计实现并通过消融验证，修改须增加配置版本。

- 多表示先映射到 canonical chunk，每一条路以最佳排名保留一次，避免同块的十个问题向量当成十条独立证据。RRF 跨路贡献仍可累加，路定义和权重明确；Multi-Query 路数增长的影响必须记录。
- BM25 使用原文/必要标题，不因假设问题数量增加而重复原文记录。
- RRF 输出与 Reranker 输入容量分开配置；最终上下文还受 token 预算约束，不仅看 TopK。
- Reranker 对查询和原文候选评分；摘要/假设问题不代替原文输入。原图描述可参与召回，但其派生属性保持可见。
- MMR 需明确 query–chunk 相关性与 chunk–chunk 相似性来源。不同尺度分数不得未经定义就相减；不能通过硬性单文档配额丢弃必要的相邻规则。
- Parent 扩展同租户同文档版本、重新授权，合并重复父章节，仍记录实际向模型发送的来源单元。超预算时按明确规则缩减，不能只记最初命中子块却忽略真正发送的父块。
- 初始实验参数可从每路 50、融合 30、最终约 6 个原文候选开始；这些是待评估起点，不是保证或业务验收阈值。扩展路数、候选和模型上下文另有总预算。

### 回答和引用

返回包含运行标识、状态、答案、事实陈述与引用关联、来源信息、必要警告。证据编号在本次运行内有效，映射到版本、chunk/图表来源单元及原文范围；不能拿答案事后搜索来猜来源。

- 程序必须验证引用编号来自本次授权上下文、范围有效，所有显示事实被 claims 表达覆盖。正文与结构化 claims 不一致时不得静默通过。
- 文字引用定位章节/段落或 PDF 页；表格保留原始位置和结构；图片描述引用原图并提示机器解析。
- 历史引用定位原来使用的版本，不自动跳到最新版本。版本已过期需提示；已删除或撤权按权限规则隐藏。
- 普通模式先执行程序校验；严格模式增加事实–证据语义检查。判定可为支持、不支持、不确定，并保留理由/证据范围。裁判不是确定性真理，不将原始 score 解释为正确概率。
- 严格检查失败/超时时不显示为“已验证”。给出未完成状态；用户可另发普通模式请求，系统不能静默把严格请求降为普通成功。
- 无授权证据时不调用模型编造企业规则；部分可答时只输出有依据部分并标明缺口。
- 不同文档说法冲突则分别引用并说明适用条件缺失，不以更新时间或排名自动认定权威。同一文档普通问答只使用当前生效版本。
- 外部资料中的“忽略系统规则”等文本不授予工具或权限。通过权限、限定工具和输出检查降低风险，不能宣称仅靠 Prompt 消除注入。

### 失败与配置行为

API 区分已完成、部分回答、证据不足、证据冲突、处理失败、取消和预算终止。前端只实时显示阶段状态，校验通过后展示完整答案。

允许的降级必须在配置中明示：如 Reranker 不可用保留融合排序，输出“未重排”；权限服务/权威数据不可用时拒绝处理，不能回退到无过滤检索。所有失败分支产生可诊断运行记录，不返回 HTTP 成功后假装答案正常。

## Testing Decisions

通过搜索/问答/引用 API 对相同题与固定候选验证策略行为；使用可控模型响应构造错误引用、无证据、冲突和格式错误。真实模型质量在 PRD-05 评估，不以固定自然语言字符串断言所有生成。当前无既有检索测试。

| 编号 | Given / When / Then |
|---|---|
| AC-03-01 | 给定原文只有错误码但问题使用同义描述，当分别运行 BM25、Dense 和 Hybrid 时，保存可比较的候选及指标，而非只保存最终答案。 |
| AC-03-02 | 给定 Rewrite/HyDE/Multi-Query 各自开关，当单独运行时，可查看派生查询、模型调用及各路命中；关闭时不存在对应调用。 |
| AC-03-03 | 给定同块多个问题表示命中同一路，当融合时，不把它们当成多个不同原文证据重复加分。 |
| AC-03-04 | 给定同主题重复候选和其他必要证据，当启用 MMR 时，选择结果及相关性代价可解释并可与关闭时对照。 |
| AC-03-05 | 给定多个子块对应同父块，当扩展时，实际上下文去重且不超过预算，引用仍指向真实发送材料。 |
| AC-03-06 | 给定模型返回不存在的来源或未覆盖额外事实，当校验时，结果不能被当成正常可引用答案。 |
| AC-03-07 | 给定资料仅支持部分结论，当严格评估时，应指出不支持/不确定部分并保留人工复核入口，不能仅凭相关性分数判真。 |
| AC-03-08 | 给定可访问证据为空，当提问时，明确说明当前资料不足，不能暗示存在某份受限文档。 |
| AC-03-09 | 给定不同文档对相同条件说法冲突，当问答时，列出冲突来源而不自行选择较新文档为真。 |
| AC-03-10 | 给定 HyDE 假想文本包含原文没有的事实，当回答时，该文本不能成为引用或知识依据。 |
| AC-03-11 | 给定重排故障，当配置允许降级时，返回带降级标记的结果；权限核验故障时不得同样放宽继续。 |
| AC-03-12 | 给定严格模式检查失败，当返回时，不能标为语义验证通过，前端未提前显示被否决正文。 |

## Out of Scope

无来源企业常识补答、联网搜索、自动裁定文档权威、默认全策略叠加、无限扩展上下文、普通用户策略编辑器、任意工具执行、绝对无幻觉承诺。

## Further Notes

策略顺序与候选参数是工程选择，不是固定行业结论。权重、阈值和默认开关必须基于分类型题集结果校准；保留失败配置有助于解释取舍。
