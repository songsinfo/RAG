# PRD-02 文档解析、生命周期与多向量索引

> **历史规格说明（2026-09-22）**：本文保留早期需求/方案基线，其中可能包含 Java、Spring、Elasticsearch、旧 Docling 入库链路或“未实现”等历史描述，不代表 `main` 当前实现。当前系统行为请以仓库根目录 `README.md`、`docs/source-walkthrough.md`、`docs/rag-evaluation-guide.md` 与 `backend/app` 源码为准。


版本：1.0 · 状态：规格已编写，未实现。依赖 PRD-01，向 PRD-03/05 提供可追溯资料。

## Problem Statement

企业资料包含文字、扫描页、图示和表格。仅提取成字符串会丢失结构；仅写向量不能处理版本、撤权或失败恢复。系统必须明确“文件已收到”“解析可用”“索引完成”“已生效”的区别。

## Solution

提供上传和一次性导入，保留原文件并解析成结构化内容，经质量检查、分块、多表示构建后发布。正常版本自动生效，异常版本进入待处理，失败不影响旧版。图片与表格可以成为证据，但机器识别内容有明确来源和限制。

## User Stories

1. 作为管理员，我希望上传 Markdown/TXT，以便快速建立文字知识。
2. 作为管理员，我希望上传 DOCX 和 PDF，以便使用常见企业资料。
3. 作为管理员，我希望导入 Wiki 导出的 HTML/Markdown及附件，以便不必先集成公司站点。
4. 作为管理员，我希望批量上传或一次性导入目录，以便减少重复操作。
5. 作为管理员，我希望查看每份文件的处理状态，以便区分上传成功与入库成功。
6. 作为管理员，我希望扫描页进行 OCR，以便其文字能够参与检索。
7. 作为用户，我希望查看机器读取的原图，以便核实识别结果。
8. 作为用户，我希望架构图和流程图有可检索描述，以便查找图示中的信息。
9. 作为用户，我希望表格保留表头、单位和相关行，以便不误解数值。
10. 作为管理员，我希望预览解析及分块结果，以便发现乱码和规则截断。
11. 作为管理员，我希望异常资料暂停发布，以便处理缺页和损坏表格。
12. 作为管理员，我希望手工确认有警告但仍可用的资料，以便不被不完美的检测永久阻塞。
13. 作为管理员，我希望重新处理失败阶段，以便恢复网络或服务故障。
14. 作为管理员，我希望重复处理不产生重复有效资料，以便安全重试。
15. 作为用户，我希望小块命中能补充父章节，以便得到完整前提与例外。
16. 作为管理员，我希望原文、摘要和假设问题分别形成检索入口，以便比较表示策略。
17. 作为管理员，我希望更新文档时旧版仍能使用，以便不中断服务。
18. 作为用户，我希望问答只使用当前生效版，以便避免过期信息。
19. 作为管理员，我希望恢复误删资料，以便纠正操作。
20. 作为管理员，我希望彻底删除能覆盖所有派生数据，以便资料不会留在其他检索入口。

## Implementation Decisions

### 输入与解析

| 输入 | 必须保留的内容与限制 |
|---|---|
| Markdown/TXT/FAQ | 标题、段落、代码块/列表边界；FAQ 的问题、答案与适用条件保持关联 |
| DOCX | 标题、正文、列表、图片、表格；无可靠分页时使用章节/段落位置，不虚构 Word 页码 |
| 文本型/扫描 PDF | 页面、文字或 OCR、表格、图片及来源位置；中文 OCR 纳入样本验证 |
| Wiki 导出 | HTML/Markdown结构、原始页面 URL、随附本地资源；不登录源站，不自动抓取外链 |

Docling Serve 作为优先解析器，经本地或内网 HTTP 接入 Java。图片提取、OCR、表格结构识别与视觉描述分别配置和记录。模型权重及语言包需固定；Unstructured 可在质量验证失败时作为替代方案，不预先承诺同时维护两套。

页面上传支持单文件及多文件。含 Wiki 附件的集合以受限导入包或管理员目录导入处理；只解析包内相对资源，拒绝路径越界、符号链接逃逸、解压炸弹及任意远程地址访问。接口不得接受普通用户任意服务器目录。

图片描述是机器解析数据，显示标识、解析版本和原图引用；看不清的数值标记未知。表格检索保留表头、单元格关系、单位和注释；长表切分时复制必要表头，不增加经营计算工具。

### 生命周期

文件接受后立即返回持久化任务标识。可见阶段包括：排队、解析、待处理、分块、构建表示、索引、已发布、失败、取消。文档另有正常、回收站、彻底删除中、已删除状态，不能把这些状态混成一个字段。

- 新文件默认仅上传管理员可读；ACL 配置按 PRD-01。
- 页面提供原文/原图与解析结果对照、标题路径、块长度、表格预览和警告位置。空内容、严重乱码、重要页面/表格提取失败触发待处理；不能声称可自动发现所有识别错误。
- 人工确认仅允许带警告继续，不能绕过权限、安全校验或让空知识冒充成功。确认人和理由审计保存。
- 索引发布所必需的解析、表示和索引阶段均成功且搜索可见后，当前版本指针才能切换；某阶段失败保留旧版。
- 为支持逐步开发，文档版本关联一个明确的索引构建配置。仅为基线构建原文向量时可以发布；当配置要求三类表示时，摘要/假设问题失败不得假装全策略可用。升级配置应触发新的构建并成功后切换，实验必须匹配实际已构建表示。
- 内容未变且解析/表示配置相同的重复提交不重复计费或生成重复有效块；相同原文但模型/配置变化不是同一次构建。
- 同一文档多个更新按服务端版本顺序处理。较早任务晚完成时不能覆盖更晚已发布版本。
- 重试具有稳定任务和产物标识、阶段检查点及次数上限；重启后可重新领取失效租约任务。不能仅使用进程内回调。
- 删除立即停止普通检索与访问；在途任务不得再次发布已删除文档。
- 恢复先核验原文件、当前 ACL 和索引完整性，必要时重建；恢复失败时不显示为可用。
- 彻底删除前给出确认及影响，删除原文件、OCR/图片/表格、块、向量与表示、索引及可定位的含内容运行制品。保留不含正文的最小审计记录。备份中副本按明确的保留周期清理；恢复备份时应用删除记录，不能使被删内容复活。

### 分块、表示与数据关系

- 分块结构优先、长度兜底，不机械按字符断开标题、否定条件、适用范围和表头。记录实际 tokenizer；字符计数不得标成 token 数。
- 文档版本包含章节/parent 与 canonical chunk。chunk 保存章节路径、原文范围、顺序及解析来源；图片和表格可有独立来源单元但继承整份文档 ACL。
- representation 记录类型 original/summary/question、生成文本、原 chunk/parent 关联、生成配置、状态及 hash。一个 chunk 可对应多个问题向量。
- 原文是权威来源；摘要和假设问题只能帮助找到它。视觉描述与 OCR 也需能定位原图，不能抹去其机器生成属性。
- Embedding 记录关联表示、模型/修订、维度、预处理和文本 hash。独立留存向量制品以便重建索引，存储形式由数据设计确定。
- 索引和原文存储逻辑分离，权限关联到真实文档，跨租户相同文本不能未经隔离直接共享缓存或派生制品。
- 具体文件大小、页数、解压量、图像像素、块长、问题数和并发上限在资源测试后锁定；无上限输入不是允许状态。

## Testing Decisions

优先通过上传/任务查询/版本查询/搜索/引用 API 验证行为。解析器故障使用可控响应，另用真实中文文档测试布局。当前无可复用实现或测试。最小样本包括列表、代码块、条件例外、合并表头、单位、扫描页、截图、流程图、损坏文件及越界附件包。

| 编号 | Given / When / Then |
|---|---|
| AC-02-01 | 给定支持的文档，当上传完成但后台尚未结束时，应返回处理中而不是已入库，任务可查询。 |
| AC-02-02 | 给定包含条件和例外的章节，当切块并读取命中上下文时，可恢复所需前提且能定位原文。 |
| AC-02-03 | 给定扫描 PDF、流程图和表格样本，当解析后，OCR、图片描述、表头/行列及来源分别可检查，不以 OCR 成功替代图片理解验收。 |
| AC-02-04 | 给定 DOCX 无可靠页码，当生成引用时，应提供章节/段落位置而不是编造页号。 |
| AC-02-05 | 给定关键页面解析失败，当执行发布时，进入待处理并指出位置；未经确认不自动生效。 |
| AC-02-06 | 给定运行到索引阶段的任务，当进程重启后恢复执行，应完成同一任务且无重复有效 chunk。 |
| AC-02-07 | 给定要求三种表示的构建，当假设问题生成失败时，不把该构建标为完整可用；旧生效构建继续服务。 |
| AC-02-08 | 给定较新的版本已发布，当较旧任务随后完成时，当前版本不能倒退。 |
| AC-02-09 | 给定 question/summary 命中，当读取知识证据时，仍定位 canonical 原文与所属版本。 |
| AC-02-10 | 给定已删除文档的在途任务，当其完成时，不能重新发布或恢复访问。 |
| AC-02-11 | 给定回收站文档，当恢复时，只有 ACL 和索引状态均有效后才参与检索。 |
| AC-02-12 | 给定彻底删除任务，当完成后，文件、派生资料、索引和含内容运行副本均不能通过应用读到；备份清理状态明确。 |
| AC-02-13 | 给定越界路径、外链或恶意附件包，当导入时，应拒绝危险资源，不能读取服务端其他文件或任意外网资源。 |

## Out of Scope

Wiki 账号登录与自动同步、直接遍历公司全量仓库、段落 ACL、Excel/跨文件业务统计、复杂图表数值的无误识别、人工审批工作流、多解析器永久并行维护。

## Further Notes

扫描件、图片和表格属于正式需求，具体可接受格式/样本应在解析技术设计中列明。质量不足必须暴露，不以支持列表代替测试结果。
