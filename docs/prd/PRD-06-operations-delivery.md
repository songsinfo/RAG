# PRD-06 运行管理、预算与交付

> **历史规格说明（2026-09-22）**：本文保留早期需求/方案基线，其中可能包含 Java、Spring、Elasticsearch、旧 Docling 入库链路或“未实现”等历史描述，不代表 `main` 当前实现。当前系统行为请以仓库根目录 `README.md`、`docs/source-walkthrough.md`、`docs/rag-evaluation-guide.md` 与 `backend/app` 源码为准。


版本：1.0 · 状态：规格已编写，未实现。服务 PRD-01～07 的运行诊断和交付验收。

## Problem Statement

模型与解析服务可能缓慢、限流或失败，异步任务可能因重启丢失。如果只记录“回答出错”，用户无法区分数据、检索和生成问题；开发者也难以证明项目能够部署和恢复。

## Solution

建立持久化运行记录、结构化阶段轨迹、有限重试、预算限制及必要审计，通过简单列表和详情查看。提供从初始化到备份恢复的可复现部署资料，不预设高可用集群。

## User Stories

1. 作为用户，我希望知道系统正在处理哪个阶段，以便判断是否继续等待。
2. 作为管理员，我希望查询失败任务及原因，以便恢复入库。
3. 作为管理员，我希望沿着运行标识查看全过程，以便定位答案问题。
4. 作为管理员，我希望区分错误与降级，以便不误判系统健康。
5. 作为管理员，我希望查看策略与模型版本，以便复现同类问题。
6. 作为项目负责人，我希望查看累计调用和费用，以便控制在线模型支出。
7. 作为管理员，我希望批量任务有并发限制，以便不阻塞用户问答。
8. 作为管理员，我希望身份和授权修改有审计，以便追踪误操作。
9. 作为项目负责人，我希望敏感正文和密钥不进入普通日志，以便避免二次泄漏。
10. 作为管理员，我希望备份后能实际恢复，以便证明资料和索引可重建。
11. 作为项目负责人，我希望测试使用独立环境，以便不误删工作资料。
12. 作为项目负责人，我希望得到部署、演示和限制说明，以便交付真实可复现成果。
13. 作为项目负责人，我希望从实际失败形成案例，以便理解工程问题而非编造经历。

## Implementation Decisions

### 运行与审计

每次请求保留运行 ID、租户、用户、模式、配置和模型版本、资料构建标识、状态及终止原因。阶段事件记录起止时间、候选/上下文证据 ID、排名/分数、调用量、错误、降级和预算消耗。

普通用户看到自己的请求状态和必要错误；管理员看到本租户运行元数据，正文级诊断仍受文档读权限约束。内部事件流不作为“模型思维链”展示，只记录可观察的工具与服务行为。

安全审计与性能日志分开：登录事件、ACL 变更、文档发布、删除/恢复/彻底删除、评测导出、配置发布必须保留行为主体、对象、时间和结果。普通日志不保存 API Key、密码、Cookie 或完整资料正文；调试证据进入受控存储。

### 预算、失败与重试

- 初始每月费用预算 100 元，单次批量实验预计 10 元。费用汇总涵盖入库增强、Embedding、问答、视觉描述、查询增强、严格验证、评估和重试。
- 创建批量任务前估算并展示调用/费用；价格或输入量无法核实时标记估算不足，不默认按零费用执行。配置已知调用/token 上限后才允许运行。
- 限制单请求模型/工具调用数、输入输出 token、候选/图片数量、总时长及并发；服务端在调用前预留预算并在返回后结算，避免并发任务各自认为余额充足。
- 金额受供应商计费差异、在途请求和舍入影响；请求数/token/时长是可执行边界，不宣称人民币金额精确封顶。
- 超时、429 和短暂服务错误可做有限退避重试；格式/鉴权/不支持文件等确定性错误不盲目重复。模型重试的费用全部记录。
- 允许的降级使用真实结果并带状态，例如省略重排；禁止自动将真实数据请求替换成 Mock 结果。测试替身仅存在于隔离测试配置。
- 权限或权威版本核验不可用时失败关闭，不能无过滤继续；严格验证失败不能标成普通成功。

### 持久化任务与资源

入库、删除清理和评估均保留任务状态，具备幂等标识、有限重试、租约/检查点和恢复处理。在线问答、批量入库、评估的并发预算分开；解析服务不承担用户鉴权决策，也不直接向浏览器开放。

部署采用单机 Java 应用、MySQL、Elasticsearch、Docling Serve 和静态前端。原文件与派生资产使用持久存储；模型密钥通过运行环境注入。容器化不代表已经实现高可用或离线模型部署。

配置和测试启动时校验环境标识，破坏性测试仅可连接明确的隔离资源。索引名称、数据库和文件目录不能意外指向工作资料；测试不自动读取公司仓库。

### 备份、恢复与保留

备份覆盖权威元数据、原文件、解析制品、需要保留的向量制品及版本配置；搜索索引可以备份或由制品重建。恢复时核对权限、当前版本、删除记录和任务状态，然后开放检索。

彻底删除后最小审计保留不含正文的标识与动作。运行内容副本、评测快照、文件及备份的具体保留期限在运维技术设计固定并公开，不能无限保存或声称立刻清除了所有离线备份。恢复备份时必须应用删除清单。

### 交付物与界限

完整交付包含：环境和版本清单、初始化/启动/关闭说明、示例账号与数据、密钥配置方法、接口说明、工程测试、冻结评测报告、备份恢复记录、演示步骤、实际问题修复记录及已知限制。

至少整理三类真实出现并处理的问题；若某类问题未出现，使用故障注入记录并明确标为模拟演练，不冒充线上事故。性能报告注明硬件、服务配置、模型、题量/数据量、并发、超时与冷/热状态。

## Testing Decisions

通过 API 和重启/故障注入验证外部行为，核心覆盖模型限流、解析失败、任务中断、预算耗尽、权限服务不可用、恢复重建。浏览器只做登录、上传、问答引用、实验详情的最短关键路径。没有既有运维测试可复用。

| 编号 | Given / When / Then |
|---|---|
| AC-06-01 | 给定一次失败问答，当按运行 ID 检查时，可确定失败阶段、配置、错误及是否发生降级，而不是只有通用错误文字。 |
| AC-06-02 | 给定模型连续 429，当达到重试/时间上限后，运行明确失败或预算终止，不无限等待；所有尝试计入用量。 |
| AC-06-03 | 给定多个并发任务接近预算，当继续请求外部模型时，统一预留与限额阻止无限超发，报告在途费用边界。 |
| AC-06-04 | 给定真实服务不可用，当生产配置执行时，不自动返回模拟知识或模拟答案。 |
| AC-06-05 | 给定持久化入库/评估任务，当进程中断重启时，可继续或明确失败，已完成阶段不会无控制重复产生有效数据。 |
| AC-06-06 | 给定敏感密钥与受限资料，当运行及错误发生时，普通日志不包含密钥或完整正文，受控详情仍执行 ACL。 |
| AC-06-07 | 给定备份以及随后彻底删除的文档，当恢复系统时，被删资料不能重新参与搜索，权限与当前版本检查通过后才对外服务。 |
| AC-06-08 | 给定未隔离的数据源配置，当启动破坏性测试时，应拒绝执行而不是清空工作索引。 |
| AC-06-09 | 给定空白运行环境，当按交付说明初始化时，可完成上传、问答、引用、评估和恢复演示，无手动改库步骤。 |
| AC-06-10 | 给定性能结果，当生成报告时，搜索耗时和完整问答耗时分别展示，注明失败/超时比例，不把搜索 QPS 当问答吞吐。 |

## Out of Scope

Kubernetes、微服务拆分、Redis/MQ 作为首版前提、容灾多活、自动生产部署、100% 可用承诺、未经许可外发公司资料、把模拟数据当真实经营数据降级。
