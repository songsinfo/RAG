# PRD-00 企业内部知识库：产品总览

> **历史规格说明（2026-09-22）**：本文保留早期需求/方案基线，其中可能包含 Java、Spring、Elasticsearch、旧 Docling 入库链路或“未实现”等历史描述，不代表 `main` 当前实现。当前系统行为请以仓库根目录 `README.md`、`docs/source-walkthrough.md`、`docs/rag-evaluation-guide.md` 与 `backend/app` 源码为准。

依据：本任务历史、grill-me 第 Q1～Q28 轮确认及后续修订。本文及模块 PRD 取代早期评估中的冲突假设。

## Problem Statement

运营、产品和技术团队需要共用企业知识。例如技术编写的订单排障指南可以向运营开放，但内部实现细节不能随同暴露。现有资料分散在文档、Wiki、图示和表格里，用户既难找到正确资料，也难知道答案来自哪份文档、是否过期。

项目负责人希望获得一套自己能够运行、理解和演示的系统，通过需求、设计、代码、失败分析与评估掌握 RAG 工程。代码全部由开发代理实现；不以用户手写 Python 或底层搜索算法为前提。项目经历必须与实际交付证据一致，不声称已经在公司上线或达到不存在的使用规模。

## Solution

建设一个 Java 主导的内部知识库：维护者导入文档并授权，用户在自己的可读范围内提问，系统提供带来源的回答，管理员通过实验和反馈定位问题。前端只实现必要操作和状态展示，主要投入后端。

### 角色与核心旅程

| 角色 | 主要行为 |
|---|---|
| 普通用户 | 登录、查看可读文档、问答、引用、自己的会话、反馈 |
| 固定维护管理员 | 管理本租户知识库、资料、授权、任务、策略、评测及运行状态 |
| 评测执行身份 | 代表指定普通用户执行隔离实验；不能把维护权限当成被测用户权限 |

“运营、产品、技术”是示例用户组，不是强制建立三套互不相通的知识库。知识库用于组织资料，文档阅读授权决定可见性。

核心旅程：管理员上传并预览 → 文档入库并授权 → 用户提问 → 查看经过校验的回答与原文 → 提交反馈 → 管理员复现实验和修正。

### 最小前端

| 页面 | 必需内容 |
|---|---|
| 登录 | 本地账号、失败提示、退出 |
| 问答 | 资料范围、问题、普通/深入模式、处理状态、取消、答案、引用、反馈、会话列表 |
| 文档管理 | 列表、上传/批量上传、预览、版本、权限、处理状态、重试、回收站 |
| 实验评估 | 题集、配置版本、运行任务、指标对照、逐题候选与证据 |
| 运行详情 | 请求阶段、错误、降级、预算、必要审计；可复用表格和详情面板 |

不建设复杂仪表盘、品牌设计或可视化流程编排器。普通用户看不到技术策略开关。

## User Stories

1. 作为运营用户，我希望阅读被授权的排障指南，以便独立处理常见问题。
2. 作为技术用户，我希望同一系统能够保存受限实现资料，以便在共享知识时不暴露全部内容。
3. 作为产品用户，我希望问题能关联规则与流程文档，以便核对业务行为。
4. 作为普通用户，我希望默认只搜索有权访问的资料，以便不需要理解权限实现。
5. 作为普通用户，我希望缩小资料范围，以便解决特定领域的问题。
6. 作为普通用户，我希望通过追问继续讨论，以便不用重复提供问题背景。
7. 作为普通用户，我希望看到引用原文和版本，以便判断答案是否可信。
8. 作为普通用户，我希望依据不足或冲突时被明确告知，以便不误用模型猜测。
9. 作为普通用户，我希望取消等待中的请求，以便停止不再需要的工作。
10. 作为普通用户，我希望提交评分、评论和问题报告，以便帮助改善答案。
11. 作为管理员，我希望批量导入多格式资料，以便快速建立可用知识库。
12. 作为管理员，我希望先看到解析结果和异常，以便避免坏数据直接生效。
13. 作为管理员，我希望文档更新失败不影响旧版，以便保持知识可用。
14. 作为管理员，我希望可恢复误删资料，以便纠正操作失误。
15. 作为管理员，我希望所有派生表示继承原文权限，以便不同检索路径都遵守同一边界。
16. 作为管理员，我希望逐项比较检索策略，以便了解收益而不是盲目叠加功能。
17. 作为管理员，我希望评估能固定资料、身份和配置，以便复现失败。
18. 作为项目负责人，我希望代码、测试和文档对应到需求，以便理解系统并说明个人项目贡献。
19. 作为项目负责人，我希望从干净环境部署和演示，以便证明项目不依赖手工修库。
20. 作为项目负责人，我希望知道实际成本和限制，以便诚实评估交付成果。

## Implementation Decisions

### 架构方向

- Java 21、Spring Boot、Spring AI 模型客户端、Elasticsearch 官方客户端、MySQL/MyBatis/Flyway、Spring Security；Vue 3/Element Plus 提供简单页面。
- Java 模块化单体负责身份、文档、任务、检索、问答、评估；独立 Docling Serve 负责结构化解析，Unstructured 仅为备选。详细版本、模型及选项在技术设计锁定。
- 文档原文件和派生图片持久保存；原文、版本和权限有权威记录，搜索索引属于可重建派生数据。
- 以单企业内部部署为主要使用形态；数据模型保留租户归属，自动测试使用第二租户验证隔离。不做商业 SaaS 管理。
- 管理员有本租户文档维护权限，阅读由文档 ACL 单独决定；未获阅读授权不能通过预览、日志、评测或导出读取正文。管理员可显式调整本租户 ACL，调整必须审计，因此它不是对恶意租户管理员的密码学隔离。
- 全部检索策略纳入交付，但可以默认关闭：Rewrite、HyDE、Multi-Query、Chunking、Parent-Child、Original/Summary/Hypothetical Question 多向量、Dense、Sparse/BM25、Hybrid、RRF、MMR、Reranker。
- 回答先校验后展示，处理状态可实时更新。单 Agent 在后期复用同一权限、检索和证据服务。

### 数据与模型边界

- 默认只用独立模拟资料或经过确认的脱敏资料。公司目录只完成元数据调查，没有获得将公司正文发往在线模型的授权，也不自动导入。
- 主体模型通过在线 API 调用。图片描述同样遵循资料外发边界；本地解析不代表后续 Embedding/生成不外发。
- 初始预算：每月 100 元，单次批量实验预计不超过 10 元；实现调用次数、token 和任务并发限制。价格变动、供应商计费及在途请求使金额不是可绝对保证的硬上限。

### 统一术语

| 术语 | 本项目定义 |
|---|---|
| 文档 | 具有稳定身份和阅读 ACL 的资料 |
| 文档版本 | 一次不可变的资料快照；新版本需成功发布才成为当前版 |
| Parent/章节 | 保留较完整上下文的原文单元 |
| canonical chunk | 可追溯到文档版本的原始知识片段 |
| representation | 原文、摘要或假设问题等检索表示，映射回原始片段 |
| evidence | 本次请求实际使用的授权原文或原图证据 |
| claim | 答案中的事实陈述，可关联一个或多个证据 |
| 检索配置 | 有版本的策略开关、参数及预算，不由模型任意修改 |
| ACL | 文档读者授权；与登录状态、维护操作资格分别检查 |
| 已验证 | 有实际测试或实验结果，不能由文档完成推断 |

### 模块规格与优先级

| 规格 | 职责 | 首次可见增量 |
|---|---|---|
| PRD-01 | 身份与权限 | 本地账号、文档读权限 |
| PRD-02 | 文档生命周期和表示 | Markdown 入库，随后多格式、多模态、多向量 |
| PRD-03 | 检索、答案和证据 | BM25 搜索，随后普通 RAG 和全部增强策略 |
| PRD-04 | 会话、取消和反馈 | 基础会话，随后完整权限失效处理 |
| PRD-05 | 评估与实验 | 30 题批量执行，随后界面、扩展题集及语义评估 |
| PRD-06 | 运行管理与交付 | 基础任务和 Trace，随后恢复、预算和部署验证 |
| PRD-07 | Agent | 普通 RAG 稳定后加入深入模式 |

完整 PRD 之后才进入详细架构、ER/DDL、API、状态机及实现。早期增量不等于完整交付。

## Testing Decisions

### 测试边界

沿用用户已确认的外部行为验收：优先从应用 API 驱动上传、授权、提问、查看历史和评测，不以私有方法调用次数作为正确性。慢速模型/解析服务在故障测试中使用可控替身；真实服务另做小样本冒烟和质量评估。浏览器只验证关键操作和状态可达。

当前项目没有业务代码或既有测试，因此没有可复用的测试边界。计划在同一个 API 集成测试层完成跨模块场景，避免为每个内部类发明新的测试协议。算法正确性仅在外部行为不能明确区分错误时增加小型确定性用例。

### 总体验收

| 编号 | Given / When / Then |
|---|---|
| AC-00-01 | 给定独立测试环境与演示账号，当管理员上传并授权排障指南，用户提问时，应得到可定位原文的回答；整个流程不需手动改数据库。 |
| AC-00-02 | 给定同租户受限文档和另一租户文档，当未授权账号从搜索、引用、历史、预览或评测入口访问时，均不能得到受限内容。 |
| AC-00-03 | 给定可用旧版，当新版任一发布必需阶段失败时，旧版继续服务；重试成功后新请求使用新生效版。 |
| AC-00-04 | 给定已生成答案，当证据权限撤销或文档进入回收站后，重新读取历史时应隐藏受影响回答和来源。 |
| AC-00-05 | 给定策略清单，当验收完整交付时，每项策略均有实现、可切换配置和实验结果；没有收益的策略可关闭，但不能缺失。 |
| AC-00-06 | 给定冻结题集，当运行基线与增强方案时，报告逐题结果、失败数、身份、资料及配置版本、质量、耗时和成本。 |
| AC-00-07 | 给定部署资料，当在干净环境按说明启动时，应完成初始化、基本运行和恢复演示；不能把仅有 Docker 命令当作部署通过。 |

工程关键验收全部通过；效果报告真实，允许暴露不足，不预置 95% 正确率或 100% 可用率。所有试验性的技术参数必须注明未校准。

## Out of Scope

商业 SaaS 计费/自助租户管理、公司 SSO、Wiki 登录抓取/自动同步、段落级 ACL、复杂审批流、经营指标计算与报表、商品推荐、多 Agent DAG、任意代码沙箱、全量逐字流式答案、高可用集群和所有复杂版面的无误识别。

不做项不包括扫描件 OCR、图片理解和表格提取：这三项经访谈已纳入范围。

## Further Notes

- 当前只有文档，没有完成软件安装、模型联通、解析性能或端到端测试。Docling 能力不等于本项目质量已验证。
- 尚需技术核实：机器资源/容器可运行性、兼容版本、中文 OCR、模型/价格/配额、上传及上下文容量参数。由实现方调查，不重新询问已确定的产品决定。
- 知识笔记分来源、概念、实践/决策三类；实践记录连接到需求、实现和实验，而不是抄录教材。
- 本地规格是本轮交付。尚未配置 Issue Tracker，不发布外部工单，不宣称已打 ready-for-agent 标签。
