# PRD-04 会话、任务取消与用户反馈

版本：1.0 · 状态：规格已编写，未实现。依赖 PRD-01/03，反馈接入 PRD-05/06。

## Problem Statement

追问需要历史，但历史可能包含已撤权或过期的资料。共享默认会话会串用户，取消请求可能只取消前端等待，反馈若无法关联原请求则不能用于改善系统。

## Solution

为每个用户持久保存独立会话，资料范围与请求状态明确，重新鉴权后才使用历史。支持取消后台请求及引用状态更新。评分、评论、问题报告关联到实际回答和运行，用于审计和评估改进。

## User Stories

1. 作为用户，我希望新建多个会话，以便分开讨论不同问题。
2. 作为用户，我希望只看到自己的会话，以便避免信息混用。
3. 作为用户，我希望历史在服务重启后仍存在，以便继续使用。
4. 作为用户，我希望追问继承选定范围，以便维持讨论边界。
5. 作为用户，我希望切换范围时得到提示，以便知道后续依据发生变化。
6. 作为用户，我希望历史引用注明旧版本，以便不把历史答案当当前规则。
7. 作为用户，我希望权限变更后受影响内容不可见，以便资料授权得到贯彻。
8. 作为用户，我希望看到请求阶段，以便区分检索中与失败。
9. 作为用户，我希望取消后不再收到迟到答案，以便停止已放弃的任务。
10. 作为用户，我希望清除会话，以便整理历史。
11. 作为用户，我希望对回答评分和评论，以便说明有用或错误之处。
12. 作为用户，我希望上报引用错误、信息过期或权限问题，以便进入处理流程。
13. 作为管理员，我希望从反馈打开关联运行，以便定位检索或生成问题。
14. 作为管理员，我希望修复后的问题进入回归候选，以便减少重复错误。

## Implementation Decisions

### 会话与上下文

- 会话与消息关联租户、所有者、资料范围和运行。没有全局共享 default 会话。会话 ID 不能代替所有者鉴权。
- 历史持久化到业务存储；送给模型的历史是独立、受预算约束的视图，不是无上限传入全量消息。
- 追问沿用会话范围，但权限每次重新求值。范围缩小/切换后开启新的上下文段：保留用户可见历史，旧范围的回答不直接进入新段，必要时提示用户补充问题。不能只改前端选择框而保持模型旧上下文。
- 当前版本更新不自动删除仍可读旧回答；页面标注历史答案引用的旧版。后续追问必须重新检索当前版，旧助手答案不能充当当前企业事实。
- 每次历史读取和上下文构造检查全部实际证据。任一资料撤权/回收站/彻底删除则整条回答及引用隐藏并用状态提示代替，不输出隐藏标题。
- 证据权限变更可能影响依赖旧回答的后续输出，需保留上下文依赖。第一版采用保守处理：对受影响回答所在上下文段的后续助手回答一并标记需重新核验；不能仅删除最初一条后让派生内容继续暴露。
- 用户清除会话后不再被问答读取；保留哪些最小运行审计由 PRD-06 明示，清除不代表供应商侧历史可撤回。

### 请求状态和取消

提交问题返回可跟踪运行。状态包括排队、检索、生成、校验、完成、失败、取消、预算终止；阶段更新不携带未校验答案正文。

- 用户只能取消自己的运行；重复取消结果稳定，不能取消别人的任务。
- 取消设置服务端状态，后续检索、模型调用或工具执行不再发起；可以中断的连接尝试中断，不能中断的请求返回后丢弃结果。
- 取消不承诺撤回已经发生的模型费用。取消与完成并发时使用明确的终态规则；若取消已被接受为终态，迟到答案不得覆盖它或进入历史。
- 同一会话第一版不并发接受多个活动问答；重复提交通过幂等标识或活动请求提示处理，避免轮次顺序混乱。

### 反馈

评分采用有用/无用，评论为可选文本；问题类型包括答案错误、引用错误、资料过期、信息缺失、权限问题及其他。保存答案/运行/提交者/时间，用户只能反馈自己可访问的回答。

问题处理先提供待处理、处理中、已解决状态和处理说明；不建设完整工单系统。管理员读取关联证据仍需权限。将反馈加入题集前由维护者核验和脱敏，不自动把用户说法当正确答案，不污染冻结测试集。

## Testing Decisions

通过会话、问答状态、取消、历史和反馈 API 验证跨用户隔离、权限变化及并发终态。使用延迟模型替身控制取消时序，避免依赖真实模型刚好足够慢。当前没有既有会话测试。

| 编号 | Given / When / Then |
|---|---|
| AC-04-01 | 给定两个用户，当他们使用相同或猜到的会话 ID 请求历史/清除/取消时，不能操作另一个用户的资源。 |
| AC-04-02 | 给定已保存会话，当应用重启后，用户仍能看到经过当前权限检查的历史。 |
| AC-04-03 | 给定旧范围内有答案，当切换范围后追问时，旧回答不直接送给模型；独立问题无法构造时要求补充。 |
| AC-04-04 | 给定旧回答依赖已撤权资料，当重新读取及追问时，原回答和受影响派生内容均不会泄露。 |
| AC-04-05 | 给定仅发生版本更新且权限仍有效，当读历史时，可见旧版标识；追问通过当前生效资料回答。 |
| AC-04-06 | 给定模型请求尚未返回，当取消被服务端接受后，即使迟到结果成功也不显示或写成正常助手答案。 |
| AC-04-07 | 给定同一会话有活动请求，当再提交问题时，得到明确提示或相同幂等运行，不产生乱序双回复。 |
| AC-04-08 | 给定一条反馈，当维护者查看时，可定位对应配置和运行；无证据权限时不能通过反馈详情读取正文。 |
| AC-04-09 | 给定无用反馈，当准备加入回归集时，未经核验不能自动成为标准答案或改变冻结题集。 |

## Out of Scope

跨用户共享会话、长期个性化记忆、Redis/MySQL/本地三级缓存、复杂客服工单、消息协同编辑和承诺取消后费用为零。

## Further Notes

仅在 UI 隐藏旧回答不够：上下文构造、反馈详情和后台查看也需遵守同一失效规则。具体依赖记录和内容保留方案在数据设计细化。
