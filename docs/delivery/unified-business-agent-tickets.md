## UA-T01：提供四个固定模拟业务工具

- 来源/目标：Spec §4；UA-02、07。建立可直接执行的业务工具契约。
- blocked-by：无。
- 范围：新增最小业务工具模块及定向测试；参考 `backend/app/qa/agent.py` 的现有工具声明，避免通用插件/HTTP 框架。
- 工作：实现 `diagnose_coupon(user_id,coupon_id)`、`get_final_price_rules()`、`diagnose_product_group(user_id,product_group_id)`、`diagnose_subsidy(user_id,activity_id)`；提供描述/schema、确定性 fixture、参数校验、结构化结果和代码生成的证据文本。保留 mock、fixtureVersion、对象及时间。
- 验收：四工具无网络无凭据可运行；缺参可识别；金额和规则符合 Spec §4；任意输入 ID 仅回显，不暗示实际查询；执行失败与业务不满足分开；参数校验、固定结果与 mock 标志有测试。
- 完成证据：合成输入/输出样例、定向测试结果。
- 风险：不得实现真实诊断规则或增加实际价格试算；不可拿模拟输出宣称业务接通。

## UA-T03：将工具接入现有 Agent，完成追问闭环

- 来源/目标：Spec §3–5；UA-03、04、05、07。
- blocked-by：UA-T01、UA-T02。
- 范围：`qa/agent.py`、`retrieval/rag_graph.py`、`claim_validator.py`、必要的会话结果处理和 Agent/检索图测试。
- 工作：注册四工具并分派执行；提示明确知识/业务来源边界；缺参用具体 gaps 追问；当前明确 ID 优先，歧义时澄清；结果进入统一证据和模型上下文。沿用已有调用预算、取消和重复调用限制。
- 检索接入：将 `search_knowledge` 内部的 `RetrievalPipeline.retrieve()` 调用替换为 `RagRetrievalGraph`；传递当前 actor/run、查询参数、检索配置及会话/评估范围，保留 ACL、阶段事件、预算、取消与 provenance。检索图仅返回证据，最终回答留给外层 Agent；不增加内层持久化 checkpoint，不扩大为独立 `/search` 和纯检索评测的入口重构。
- 验收：脚本化 fake model 能完成四工具、知识检索和混合工具闭环；规则工具无需用户 ID；补参后继续调用；切换对象不复用上一用户结果；业务结果足够时可以直接完成；未知工具/失败/超限不编造结论。
- 检索验收：通过调用链测试确认工具实际进入 `RagRetrievalGraph`；验证参数/配置/权限范围传递、阶段事件、证据回填、无证据与失败传播；取消和预算限制仍有效，检索节点不被重复计为 Agent 工具调用。
- 完成证据：可重放的合成对话轨迹、定向测试；标明 fake model 不证明真实模型选择质量。
- 风险：不要增加入口 RAG/Agent 分类器或为四业务新增四个 Agent。

## UA-T04：统一新问答执行入口并兼容旧请求

- 来源/目标：Spec §3、6；UA-01、08。
- blocked-by：UA-T03。
- 范围：`qa/router.py`、`service.py`、`runtime.py`、worker/恢复调用点与 API 测试。
- 工作：所有新问答使用现有 Agent DURABLE 执行机制；无 mode 请求可用，旧 mode 输入统一规范化；保留会话归属、幂等、预算、取消及 SSE。记录旧运行/旧排队任务处理步骤，不改写历史模式。
- 验收：缺省/RAG/AGENT 三种请求进入同一 Agent 链；不为新请求创建普通 RAG REALTIME 执行；重复提交不重复执行；取消、失败、恢复和事件测试通过；旧历史读取仍成立。
- 完成证据：API/worker 定向测试、兼容输入样例、迁移及回滚步骤。
- 风险：切换执行通道可能影响排队时延；记录阶段耗时，不凭架构声称加速。
