状态：IN_PROGRESS（PR #14 已合并 `main`，以下 Tickets 的生产验收尚未全部完成）。日期：2026-10-09；更新：2026-10-10。规格：[统一业务 Agent](../design/10-unified-business-agent-spec.md)。
本文件保留原任务/验收合同；T08 的授权跨 run 快照、版本/压缩边界已经编码，但不能据此视为长期正确性、真实缓存收益或全部验收完成；详见[实施状态](unified-business-agent-implementation-status.md)。所有 Java 接口均不接入，四个业务工具只返回明确标注的模拟数据。

## UA-T01：提供四个固定模拟业务工具

- 来源/目标：Spec §4；UA-02、07。建立可直接执行的业务工具契约。
- blocked-by：无。
- 范围：新增最小业务工具模块及定向测试；参考 `backend/app/qa/agent.py` 的现有工具声明，避免通用插件/HTTP 框架。
- 工作：实现 `diagnose_coupon(user_id,coupon_id)`、`get_final_price_rules()`、`diagnose_product_group(user_id,product_group_id)`、`diagnose_subsidy(user_id,activity_id)`；提供描述/schema、确定性 fixture、参数校验、结构化结果和代码生成的证据文本。保留 mock、fixtureVersion、对象及时间。
- 验收：四工具无网络无凭据可运行；缺参可识别；金额和规则符合 Spec §4；任意输入 ID 仅回显，不暗示实际查询；执行失败与业务不满足分开；参数校验、固定结果与 mock 标志有测试。
- 完成证据：合成输入/输出样例、定向测试结果。
- 风险：不得实现真实诊断规则或增加实际价格试算；不可拿模拟输出宣称业务接通。

- 工作：实现 DOCUMENT/TOOL 类型；保存工具快照及关联元数据；按类型处理来源注册、去重、权限复核、详情/历史、Judge；保留现有引用协议。确定最小向后兼容 schema，不用伪文档占位。

## UA-T03：将工具接入现有 Agent，完成追问闭环

- 来源/目标：Spec §3–5；UA-03、04、05、07。
- blocked-by：UA-T01、UA-T02。
- 范围：`qa/agent.py`、`retrieval/rag_graph.py`、`claim_validator.py`、必要的会话结果处理和 Agent/检索图测试。
- 工作：注册四工具并分派执行；提示明确知识/业务来源边界；缺参用具体 gaps 追问；当前明确 ID 优先，歧义时澄清；结果进入统一证据和模型上下文。沿用已有调用预算、取消和重复调用限制。
- 检索接入：将 `search_knowledge` 内部的 `RetrievalPipeline.retrieve()` 调用替换为 `RagRetrievalGraph`；传递当前 actor/run、查询参数、检索配置及会话/评估范围，保留 ACL、阶段事件、预算、取消与 provenance。检索图仅返回证据，最终回答留给外层 Agent；不增加内层持久化 checkpoint，不扩大为独立 `/search` 和纯检索评测的入口重构。
- 验收：脚本化 fake model 能完成四工具、知识检索和混合工具闭环；规则工具无需用户 ID；补参后继续调用；切换对象不复用上一用户结果；业务结果足够时可以直接完成；未知工具/失败/超限不编造结论。
- 检索验收：通过调用链测试确认工具实际进入 `RagRetrievalGraph`；验证参数/配置/权限范围传递、阶段事件、证据回填、无证据与失败传播；取消和预算限制仍有效，检索节点不被重复计为 Agent 工具调用。
- 完成证据：可重放的合成对话轨迹、定向测试；标明 fake model 不证明真实模型选择质量。
- 风险：不要增加入口 RAG/Agent 分类器或为四业务新增四个 Agent。

## UA-T08：实现稳定追加上下文与低频压缩

- 来源/目标：Spec §5.4；UA-10、11。控制上下文大小，同时减少可缓存前缀变化。
- blocked-by：UA-T03、UA-T04。
- 范围：`qa/runtime.py`、`agent.py`、`context.py`、必要的会话持久化/迁移、工具结果适配及 `retrieval/rag_graph.py` 的上下文预算接入。
- 工作：固定提示词与工具顺序；正常追加消息，首次回填工具结果就限长；将上下文组装与业务状态分开，持久化快照版本/压缩边界/来源依赖，跨提问复用。完整请求预算包含工具定义、其他 schema、输出预留与安全余量；实现高低水位、完整交互组裁剪及硬上限失败。初值按 Spec，不能每轮重写前部状态或重新压缩相同无进展内容。
- 工作：修复旧历史初始化的最近轮次优先问题；保留待补参数及 NEED_CLARIFICATION 上下文；快照不升级为指令或独立证据，处理旧 run 引用；恢复遵守租约与幂等，撤权时处理派生状态和快照。保留外层轮数、工具次数、重复调用与累计预算限制。
- 验收：捕获连续请求验证未压缩时前缀及工具定义不变；超阈值后留下增长空间；大结果、中文估算、输出预留、硬上限、不可拆工具组、无进展压缩均有测试；跨轮补参/切换对象/恢复/撤权不串数据、不重复追加、不产生无效引用；mock 标志不丢失。
- 完成证据：上下文生命周期与存储迁移说明、合成请求对照和定向测试；不把前缀一致性测试称为真实缓存命中。
- 风险：压缩会改变部分前缀，权限变化也必须使旧内容失效；不为缓存保留无用或不可访问内容，不引入额外总结模型。

- 来源/目标：Spec §5.4；UA-12。

- 工作：透传供应商支持的缓存读取 Token、输入 Token、模型/部署、延迟与费用，缺失字段记未知；记录压缩事件及版本，不额外记录业务明文。核对实际 LiteLLM/供应商能力后再配置可选缓存参数；不为本任务更换供应商或移除故障 fallback。
- 验收：合成 usage 覆盖缓存命中、零命中和字段缺失；版本及压缩原因可追踪；准备相同模型/场景下追加、压缩前后请求的真实对照步骤，排除响应缓存对观测的混淆；同时记录正确性、总输入量、缓存读取量、耗时和可用费用。不得承诺固定命中率，未运行时明确未实测。
