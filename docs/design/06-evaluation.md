# 评估系统与可复现实验

对应 PRD-05；安全、成本与工程测试遵循 PRD-01/06。产品模块包含题集管理、冻结、批量执行、配对对照、逐题诊断、裁判和人工复核，不是最后手工跑一次脚本。

## 1. 数据集与金标准

30 题冒烟集起点配额：精确事实 6、语义换述 4、条件/多证据 4、多跳 3、追问 3、无答案 3、冲突 2、撤权/跨租户/旧版 3、OCR/表格/图片 2。类别可多标签；安全反例另有确定性 API 测试集，不用这 3 题替代权限测试。扩至约 100 题时补齐每类，少样本注明不确定性。

每题 JSON 逻辑结构：
- caseKey、groupKey、split、category/tags、question 或 conversationTurns；
- persona（隔离环境的租户/用户/组快照）、scope、时间条件；
- expectation=ANSWER/PARTIAL/ABSTAIN/CONFLICT；
- requiredFacts：需要回答的要点、允许的替代措辞；
- evidenceGroups：每组是必需事实，组内是可替代原文锚点；
- anchor：原始系统/租户/文档、version SHA-256、原文件位置、quote hash；图表另有页/框/单元格；
- relevanceLabels、标注来源、人工状态。

同一事实组的替代来源只需命中一个，不同必需组要分别覆盖。示例：订单重试题要求 A“检查幂等键”、B“检查重试上限”、C“检查补偿日志”，Top5 只找到 A 则 Hit@5=1、Recall@5=1/3。

开发代理生成初稿并以实际模拟原文核对，标注状态先 AUTO_REVIEWED；供用户抽查/人工更正，不标成人工全量审核。冻结记录谁审核、哪些仍自动标签。

groupKey 把近重复问法、同会话追问放同一分区；初始按组约 60% DEV/40% TEST，实际数量随分组记录。所有调参使用 DEV；冻结 TEST 不因本轮效果差而改答案。公开小测试集被多次使用后应承认存在调参污染风险，下一版增加独立题。

## 2. 快照与索引策略

eval_snapshot manifest 固定：语料原件 hash、版本、解析配置/制品 hash、可选 build 集、ACL persona、原始来源 lineage、环境 ID。检索配置固定模型端点标识/revision/dims、Prompt hash、价格版本、查询开关、候选上限、种子设置、并发和时限。

同一原始快照可有多个分块/表示 build，原文锚点分别映射至各 build 的 source_unit/chunk。映射先行校验，不可映射的题列为 ANCHOR_UNRESOLVED 并阻止该比较冻结；不能悄悄当成策略漏召回。

评测独立数据库、ES 前缀和文件根，首版另起相同 Java 应用 evaluation profile；运行 persona 来自该隔离环境种子账号，API 管理员资格不传递给被测用户。业务检索/问答服务完全复用。

首版只导入模拟或已确认脱敏快照。若以后使用受限来源，原资料 authority 必须可联系以进行查看/导出核验；源不可用时失败关闭，不能因为权限快照里过去允许就继续展示。origin lineage 和 purge 域确认用于移除评测副本。

## 3. 执行状态与幂等

DRAFT → 校验/估算 → QUEUED → RUNNING → COMPLETED / FAILED / CANCELLED / BUDGET_EXCEEDED。
RUNNING 保存已完成/失败/未开始数量；部分完成不是正常完整报告。每个 eval_result 唯一键 (run,case,repeatNo)，保存对应真实 qa_run ID，不复制一份失去权限关联的答案。

启动时先为计划的全部 case 建 PENDING 结果，再逐题调用 AnswerService。这样未开始、超时、失败都在计划分母中。每题使用由 eval run + case + repeat 构造的幂等 key；任务重启先查旧 qa_run，不能重复收费重跑已成功题。

重启遇到 PROCESS_RESTARTED 的在线子 run，保留失败；管理员明确选择新实验版本/新运行重跑，而非覆盖旧结果。裁判失败可单独重试，其 attempt 和费用仍计账，不重复业务问答。

每题完成后持久化候选/上下文/声明及指标，汇总可增量重算；取消停止未启动题和后续模型调用，已完成保持。同一评测实验首版并发 1，在线应用使用独立配额。

## 4. 指标数学口径

以有标准事实组的可答题为检索评估集合 Q。TopK 指去重 canonical child 排名；父扩展后的实际上下文另算 context coverage。

- Hit@K：每题至少命中一个合格组为 1，否则 0，宏平均。
- Recall@K：每题已覆盖必需组数/必需组总数，再宏平均。失败和超时在可答题的该指标记 0；明确区分额外的“成功样本条件指标”。
- MRR：首个合格证据 rank 的倒数，未命中 0。
- nDCG：gain=2^grade−1，DCG@K=Σ gain_i/log2(i+1)，除以同标注候选空间理想排序 IDCG；IDCG=0 标 N/A。grade 0..3，3=直接充分、2=部分、1=相关但不支持、0=无关。初版对比较配置的候选池统一标注并报告未判定比例；不同分块只在完成重标后比较 nDCG，跨块大小主要比较锚点事实组召回。
- ANN Recall@K：同过滤候选、模型、向量、距离下 ANN TopK 与精确 TopK 的交集大小/min(K,可用向量数)。并列边界固定 ID 排序，表示级指标与 canonical 业务召回分开。
- Context coverage：实际发送材料覆盖的必需组比例；冗余按规范原文重复 token/总原文 token，报告 tokenizer，不用字符比例冒充 token 比例。
- 任务成功：按题的 expectation 及完整事实/正确引用/所需终态共同判定；全计划题中成功数/计划数，同时列出未运行数和完成覆盖率。部分实验不得只展示成功均值。
- 正确性：CORRECT/PARTIAL/WRONG/UNDETERMINED，只有满足全部必需事实且无错误声明算 CORRECT。引用格式合法与语义正确分别报告。
- 事实支持率：受支持 claims/待判断 claims，未知计入待判断分母并单列。零 claims 标 N/A，不能给 100%。
- 引用精确率：真正支持对应 claim 的引用关联数/全部关联数；引用覆盖率：有支持性引用的 claims/需引用 claims。单独报告程序格式通过率。
- 应拒答召回：应拒答题正确拒答数/应拒答题；另报可答题错误拒答率，防止全部拒答刷分。
- 权限：逐例 pass/fail 与泄漏的元数据/正文/派生类型，任何泄漏阻断工程验收。
- 性能：按检索、外部模型、解析、整题分别 P50/P95（nearest-rank）；包含失败题已观察耗时，超时注明右截尾和超时阈值，不能当真实完成延迟。吞吐分别统计检索请求与整题问答。
- 成本：所有尝试 input/output token、费用实际/估算/未知、调用数；未知费用不填 0。

## 5. 必跑实验矩阵

| 实验 | 固定项 | 变量与判读 |
|---|---|---|
| B0/B1/B2/B3 | 同原文和 child 构建 | BM25 / Dense / Hybrid-RRF / Hybrid-RRF+Reranker |
| Q1/Q2/Q3 | B3 配置和快照 | 单独 Rewrite / HyDE / Multi-Query；记录派生查询及失败 |
| C1 | 同原始语料、模型、题目锚点 | 固定 token 分块与结构分块，观察完整规则召回与解析边界 |
| P1 | 同 child 排名、相同预算 | Parent 开/关，观测上下文覆盖和挤占 |
| V1/V2/V3 | 同 child、同模型与检索权重 | Original+Summary / Original+Questions / 三表示，对比 Original |
| M1 | 同融合/重排候选 | MMR 开/关，覆盖、冗余与代价 |
| S1 | 固定配置、匹配问题 | 普通程序检查与严格语义检查；另在同一冻结候选答案集上独立比较 verifier |
| A1 | 同模型、资料、题集 | 普通与 Agent；多跳收益和简单题额外成本 |
| D1 | 固定代表性原文件 | OCR 字错率、表格结构/单元关系、图片描述事实抽检 |

配置整体比较不能保证模型输出一致；报告温度/种子是否实际被服务支持。额外小样本做 3 次重复评估展示波动，预算不允许则明确只测一次。先单项消融，再选少量组合，禁止全开之后归因到某一个策略。

## 6. 裁判、人工复核与诊断

裁判输入严格是问题、标准要点、实际 claims、对应真实证据和固定规则，被测文档/答案都标记为不可信材料。输出各维度标签、支持位置、短理由，不索要模型隐藏推理。裁判不能调整系统权限或访问额外公司资料。

自动结果原样保留，人工 eval_review 追加新标签和理由；报告同时给自动与复核后结果，并标复核覆盖率。人工纠正样例不回写旧冻结题集，标准标注错误通过新版本修复。

逐题页按阶段展示：
原问题/独立问句 → 每路命中 → canonical 去重/RRF → 重排/MMR → 实际上下文 → claims/引用 → 自动与人工判定 → 耗时/预算。
失败归因标签为 corpus_missing、parse_error、anchor_error、retrieval_miss、rerank_drop、context_drop、generation_error、citation_error、permission、provider_failure、budget；可多标签，不由一个总分掩盖。

## 7. 导出与验收

默认导出配置、hash、分类指标、脱敏问题和必要 ID；不导出原文、完整 prompt、原图、密钥。FULL 模式显式选择且逐个来源授权，生成时和下载时都检查当前权限；导出文件登记来源、保留 24 小时，撤权立刻禁读并清理任务跟进。

验收要交出：30 题可运行样本、约 100 题冻结包、全策略实验清单与逐题报告、裁判复核记录、权限反例、失败分母和成本说明。此文没有提供任何已经测得的准确率。
