# 实施计划、运行预算与验收

> **历史设计说明（2026-09-22）**：本文保留早期技术设计基线，其中可能包含 Java、Spring、Elasticsearch、旧 Docling API/切块方案或尚未落地的设计，不代表 `main` 当前实现。当前系统行为请以仓库根目录 `README.md`、`docs/source-walkthrough.md`、`docs/rag-evaluation-guide.md` 与 `backend/app` 源码为准。


对应 PRD-00/06，整合其余 PRD 的外部验收。技术设计完成后按纵向流程编码，每阶段都提供启动方法、API 示例、真实调用链解释和实际失败记录。

## 1. 实现阶段

| 阶段 | 实际产物 | 退出检查 |
|---|---|---|
| C1 最小闭环 | Maven/前端骨架、Flyway、登录/组/ACL、私有文件、MD 上传、持久入库、BM25、30 题执行骨架 | 空白隔离环境启动；运营/技术/第二租户 API 隔离；上传到搜索闭环；任务重启恢复 |
| C2 普通 RAG | 真实模型适配与预算、Dense/Hybrid/RRF/Rerank、claims/引用、会话/取消/trace | 四基线可比较；伪造引用失败；撤权与取消竞态测试；未知成本可见 |
| C3 文档与索引 | Docling 契约、PDF/DOCX/Wiki/FAQ、OCR/图表、Parent/多表示、质量审核、版本/删除恢复 | 代表样本逐类通过；发布竞争/租约过期不复活；彻底删除覆盖副本 |
| C4 评估与策略 | Rewrite/HyDE/Multi-Query/MMR、严格模式、冻结题集、对照/复核/反馈页面 | 全部策略有开关与消融；逐题证据完整；评估权限和预算失败可重放 |
| C5 Agent 与交付 | 两只读工具、全局预算循环、完整演示、恢复演练、性能与简历证据 | 普通/Agent 配对报告；所有 AC 对应检查完成；干净部署与恢复 |

第一份可运行实现目标是 C1，不能为一开始堆齐全部策略推迟闭环。完整项目的完成度包含 C1～C5；只完成 C1 不写“已实现完整企业级 RAG”。

## 2. 工程测试边界

主要从 HTTP API 测外部行为，使用真实 MySQL/ES 容器和独立文件根；替换外部模型/解析服务生成可控响应。少量纯函数测试用于 ACL 真值表、RRF/MMR 与指标数学，避免给每层重复写模拟测试。

必须具备的并发/失败用例：
- 两租户访问已知资源 ID，正文、标题、图、引用、历史、反馈、导出、Agent 全部受控。
- 同时入库 v2/v3，v3 先发布后 v2 完成；v2 不覆盖 v3。
- 回收/恢复与旧 worker 返回并发，lifecycle fence 阻止复活。
- ES Bulk 部分失败、写成功 SQL 未切换、进程重启恢复；老版持续可检索。
- 权限撤销卡在模型请求体提交前、提交后、生成后；不泄露新内容且准确描述在途边界。
- 两次同幂等 key、不同 payload、同会话双提交；保证活动运行唯一。
- 取消先于完成/完成先于取消/迟到付费调用；终态不可覆盖且费用不漏。
- 并发预算预留、429、模型超时未知结算、Strict 超时、未知工具、嵌套调用不重置限额。
- 冻结题修改、金标准锚点失配、评估缺索引能力、全拒答、失败样本分母。
- purge 后旧备份恢复、导出已生成后撤权、评测实例离线；不恢复已删正文。

每条 PRD AC 与未来测试入口见追踪表。测试名称是计划，未创建或运行的检查不写 PASS。

## 3. 配额与费用协议

设计初始硬约束：
- 普通问答全局外部模型调用最多 8 次；Agent 最多 12 次（含全部嵌套），主循环 6、工具 8；每 run 输入累计 30,000 token、输出累计 6,000 token。
- 常规问答 deadline 45 秒，Agent 60 秒，单模型调用超时不超过剩余 deadline；入库每阶段独立较长时限，需锁版实测后设定。
- 单用户活动在线问答 1；应用在线 2、入库 1、评估 1；所有模型 HTTP 在途并发合计 3，解析并发 1。评估独立应用仍受同账号外部预算控制。
- 月预算初始 100 CNY；单次批量实验估算上限 10 CNY；调用/token/任务数才是确定可执行限制。

如果开发和评测是两个进程且共用供应商账户，必须共同使用同一预算权威：首版由主应用提供仅内部服务身份可访问的预算 reserve/settle 接口，评测模型客户端每次调用它，预算数据库不复制。主应用不接收评测正文，仅接收用途、模型配置、最大 token 和调用 ID。主预算不可用时停止新付费调用。不同供应商账户可独立预算，但报告分别列出，不能双算同一个 100 元。

ModelGateway 流程：计算 token 上界和价格快照 → 短事务预留额度/调用计数 → 登记 attempt → 复核来源权限 → 通过 Spring AI 发送 Chat/Embedding，或通过受控扩展适配发送 Rerank → 按 usage 结算，回收已确认未使用预留。Spring AI 自身重试关闭，由网关为每次 attempt 统一重试和记账；不得绕过 gateway 直接从 Docling/裁判/工具发付费请求。

价格未知不能用 0 通过批量估算。管理员须配置服务价格、币种及换算版本或可信上界，按已知最大输入/输出预留。供应商未提供准确 tokenizer 时标估算，硬限制采用保守字节上界加上下文上限，报告不是精确 token 统计。超时不知是否消费记 UNKNOWN，保留预留，人工/供应商 usage 对账前不当作免费释放；模型重试生成新的 attempt。

达到限额先停止新调用，不用 Mock 替换真实输出。已发在途费用不可撤回，人民币预算受价格/汇率和供应商计量影响，不承诺完全精确封顶。

## 4. 配置、部署与隔离

C1 启动探测：直接可执行的 JDK 版本、Maven/Wrapper、Docker 服务连接、容器资源上限、端口占用和磁盘空间；目前仅发现 CLI 路径，不等于 Docker daemon/硬件已验证。Windows 命令统一 PowerShell .ps1，不嵌套其他 shell。

部署资料最终包含 compose 配置、环境变量样例、初始化/启动/关闭/重建脚本和锁版清单。Java 开发可在 Windows 运行，Docling/MySQL/ES 在 Docker Linux 容器；宿主操作仍使用 PowerShell。

配置必须显式给 app.environment=demo/evaluation/test、数据库名、ES 前缀、artifactRoot/importRoot。自动化破坏性测试只接受 test profile + 数据库标记表 token + test_ 前缀 + 临时文件根同时通过，连接串指向工作库就启动失败。不能仅凭环境变量名字就执行清理。

公开入口只有浏览器同源服务；ES/MySQL/Docling 绑定内部容器网络或 localhost，并有凭据。健康检查 READY 要核对迁移、权限可用、生效索引和模型配置；付费模型不靠每次健康检查真实调用。

## 5. 日志、保留与恢复

| 数据 | 初始保留策略 | 清理与限制 |
|---|---|---|
| 原件/解析/向量制品与历史版本 | 文档存续期间保留 | 彻底删除任务移除；当前仍读得到的历史引用不能静默丢原件 |
| 回收站 | 30 天后进入 purge 队列 | 页面显示计划日期；管理员可提前恢复/彻底删除 |
| 用户会话正文 | 90 天或主动清除，以先到为准 | 过期删除正文及派生；历史状态提示 |
| 受控运行详情/模型调试内容 | 30 天 | 删除后只保留统计，正文不进普通日志 |
| 普通运行日志 | 14 天 | ID/错误/耗时；无问题全文、文档正文和 Cookie |
| 用量和无内容审计 | 180 天 | 保留统计/对象 ID；不保留原始供应商错误正文 |
| 评测冻结样本/报告 | 未删除来源且有需要时保留，180 天复核 | 来源撤权禁止展示；purge 清理正文和相关标签内容 |
| 导出包 | 24 小时 | 来源重新授权后下载，过期任务删除 |
| 备份 | 每日一份，最长 7 天 | 仅受控存储；删除不能声称立刻擦除所有备份 |

被冻结评测引用的 qa_run、run_event 和裁判内容适用评测保留策略，不被普通会话 90 天/诊断 30 天清理提前破坏；它们仍立即服从来源撤权/彻底删除。导出包以 EXPORT job 的 checkpoint 登记私有存储键、eval run ID、来源集合与到期时间，不强行挂到某一个 document 的 artifact 表，下载沿 job 关联重新鉴权。

备份同时覆盖 MySQL 与私有制品，首版进入维护模式暂停上传/发布/清理后取得一致快照；ES 可由 build 制品重建，保留向量避免恢复付费重新计算。备份有 manifest/hash、时间、schema/模型/配置版本，并执行一次真实恢复演练。

删除清单追加写入单独持久存储并比普通快照更新，恢复必须先应用最新清单、使任务租约失效、重建/验证索引与权限，再开放读取。清单不可得则不开放恢复后的内容服务。

彻底删除顺序：取消相关运行 → 清空/撤销导出与评测内容并等域确认 → 清理依赖运行正文并移除相关 run_source 行 → 清除 active_build 指针 → ES → 表示/span/child/parent/source_unit/build/version → artifact 文件与记录 → 保留 document 墓碑、删除记录和无内容审计。先删 source_unit/version 再删 artifact，避免来源外键阻止清理；先删 child 再删 parent。涉及评测版本引用的 snapshot_document 先移除，相关题目/金标准/人工理由清空并把快照/数据集标 PURGED；冻结不可变原则不阻止依法定产品删除语义清除内容，原 hash 和删除审计保留。未确认全部域清理保持 PURGE_PENDING，备份到期是独立状态。

## 6. 文档与学习产物

每阶段同步：
- sources：实际阅读的官方接口/源码位置及版本。
- concepts：问题→机制→代价，关联本项目实现。
- practice：一条真实请求的类/方法/SQL/调用顺序；实际遇到的问题、复现、修复与检查。
- delivery：部署、演示、冻结结果、故障注入/恢复记录、已知容量和未验证项。

至少整理三类实际问题；没有真实故障就明确标为故障注入，不写成公司线上事故。不要求用户手写全部 Python 或 Java；要求能解释实际调用链、为何失败和怎么验证修复。

## 7. 写入简历的完成标准

可写“个人项目，企业知识库 RAG 系统”的完整版本需：
1. 空白环境按脚本完成登录→上传→权限→索引→问答→引用→评估闭环。
2. PRD 验收表对应的工程检查通过，特别是权限/删除/取消/并发/恢复。
3. 所有承诺策略有实现、开关和可复现实验；负结果也记录。
4. 使用真实模型、冻结数据与标准口径产出质量/成本/性能报告。
5. 用户能够结合代码解释至少一个完整请求和三类问题处理。
6. 简历规模、收益仅引用真实测量；注明模拟语料与个人项目，不使用别人的“100 人”“千万 DAU”“100% 可用”数据。

设计本身还不满足这些条件。首份实测报告之后才能填写提升比例和吞吐，前端简单不影响后端工程完成度的评判。
